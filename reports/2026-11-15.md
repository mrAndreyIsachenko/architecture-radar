## Detailed Reviews

### `juanfont/headscale`

Current head `520eb6f9c7f90bad7a5358ea818267edf4d0b4de` adds a clearer server/CLI boundary without changing the core reconnect model. The important source change is in `cmd/headscale/cli/utils.go:92-425`, where `serverConfig()` strips CLI-only API keys before server startup, `cliAPIKey()` resolves remote bearer tokens, `dialHeadscaleSocket()` fails immediately on an empty socket path, and `hasMachineOutputFlag()` asks Cobra for the parsed command output mode instead of scanning raw argv. `cmd/headscale/cli/utils_test.go:1-116` pins the new boundary and the bypass-validation path, and `docs/about/clients.md` now documents client update control-flow for operators.

The reusable mechanism is still the reconnect/recompute split in `hscontrol/state/state.go` and `hscontrol/policy/v2/policy.go`, but the current head sharpens the trust boundary around the CLI entrypoint. That is useful because it prevents the server from consuming CLI-only secrets and removes a retry loop that can never succeed when the socket path is empty. The remaining blocker is unchanged: live reconnect storms, mixed-role HA churn, and tagged-node restart churn still need operational proof.

### `PX4/PX4-Autopilot`

Current head `c4b8f107ae97d643fc784a394e3874f34caec563` keeps the commander/failsafe model intact while broadening the validation surface. The core command path in `src/modules/commander/Commander.cpp:866-930,2858-2896` still classifies commands into accepted, denied, temporarily rejected, unsupported, and failed, then publishes the ACK. What changed is the surrounding validation stack: `test/test_mavlink_param_validation.py:108-260` now makes unsupported mission/command slots explicit, `test/mavsdk_tests/test_multicopter_failsafe.py:12-70` exercises GPS, baro, and magnetometer loss in mission flow, and `test/mavsdk_tests/autopilot_tester.py:810-863` centralizes command ACK retries and checks.

The reusable mechanism remains the same: high-risk transitions are explicitly acknowledged and the test suite encodes the expected recovery path. The current head is stronger because it makes the parameter-slot contract and the sensor-loss recovery path more legible at the test layer, but it still needs live SITL validation before it is adoption-ready.
