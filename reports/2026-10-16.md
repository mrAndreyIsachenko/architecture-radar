## Detailed Reviews

### `TencentCloud/TencentDB-Agent-Memory`
The proxy still matters as a reusable marker-gated rewrite and session-recovery pipeline, but the new head is interesting because it extends the agent-prefix registry to `dsh`. That keeps auxiliary routes from falling through the gate and shows the route map is meant to be maintained as a first-class control plane, not as ad hoc path handling.

The end-to-end flow remains: request enters `createApp()` -> prefix gating and route registration in `src/server.ts` and `src/routes/whitelist.ts` -> `InjectionPipeline.process()` rewrites the body -> session-init orchestration recovers or initializes state -> `mem:` command interception and storage backends complete the path. The open operational gap remains live proxy validation against a real upstream and persistent backend.

### `google/sam`
The same sidecar-backed mesh runtime still underpins the value here, but the current head adds a useful control-plane rule: nodes enrolled without a last-seen instant are treated as seen now before GC. That keeps silent bootstrap members from being immediately reaped while preserving the retention sweep.

The verified path is now: node bootstrap -> sidecar/API gating -> mesh discovery and tool invocation -> control-plane enrollment view normalization -> `gcExpiredNodes()` sweep -> tests for retention and multi-node mesh behavior. The source is stronger than a README-level sidecar demo, but it still needs fleet-scale churn proof.

### `trezor/blockbook`
Blockbook continues to be a strong reuse baseline for reorg-safe indexing because the sync worker still couples retry normalization, fork recovery, and bounded stalls. The new head adds a separate but analogous projection rule in the Ethereum parser: suppress pseudo-token transfers before they reach the materialized event stream.

The verified path is: `ResyncIndex()` -> `resyncIndex()` -> `handleFork()` / `connectBlocks()` -> RocksDB projection, with `ethparser.go` filtering Polygon `0x...1010` and EIP-7708 system-address flows. The open question is replay correctness: the filter looks right in source, but we still need a representative chain replay to prove it does not hide legitimate transfers.
