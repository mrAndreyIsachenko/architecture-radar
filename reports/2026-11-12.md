## Detailed Reviews

### RightNow-AI/autokernel

This repository informs `ai-llm-systems` through a persisted optimization loop with an explicit benchmark gate. The current head adds a dedicated prefill-TTFT benchmark path, cache validation, and end-to-end verification around the existing orchestration state machine, so the reusable mechanism is the stateful optimization ledger and its repeatable correctness gate rather than the GPU workload itself.

- `E1 source verified`: `orchestrate.py` defines `MOVE_ON_CRITERIA` and persists keep/revert decisions into the orchestration state.
- `E1 source verified`: `engine/prefill_ttft.py` defines the TTFT benchmark contract, cache validation, cold and warm modes, and streamed-request timing.
- `E1 source verified`: `verify.py` loads the model, applies optimized kernels, compares outputs, and writes the verification summary.
- `E2 test verified`: `tests/test_gqa_prefill_attention.py` covers the calibrated attention oracle, paged KV handling, page-size overrides, and peak calibration behavior.
- `E2 test verified`: `tests/test_calibrate_attention.py` covers calibration and backend-selection behavior.
- `E2 test verified`: `tests/test_gqa_prefill_attention_kernel.py` covers the kernel-facing prefill attention path.

The end-to-end flow is: plan extraction -> persisted orchestration state -> benchmark and calibration checks -> verification against the model -> recorded results. The main limitation is still runtime validation on a real GPU-backed workload. See [RightNow-AI/autokernel](../repositories/RightNow-AI-autokernel.md).

### TencentCloud/TencentDB-Agent-Memory

This repository informs `ai-llm-systems` through a staged proxy and session-memory pipeline. The current head adds more explicit bootstrap wiring, shared session-init orchestration, and memory-command handling around the request-rewrite path, so the reusable mechanism is the control-plane split between request preparation, session recovery, and command interception.

- `E1 source verified`: `MemoryProxy/src/index.ts` wires bootstrap, request preparation, storage initialization, and graceful shutdown with flush handling.
- `E1 source verified`: `MemoryProxy/src/pipeline/stages/session-init-orchestrate.ts` factors shared session-init recovery and gate handling into a reusable orchestration stage.
- `E1 source verified`: `MemoryProxy/src/pipeline/stages/mem-command.ts` isolates `mem:` command parsing and execution.
- `E1 source verified`: `MemoryCore/src/core/tdai-core.ts` wires the core initialization and background pipeline management.
- `E2 test verified`: `MemoryProxy/scripts/qa/p1-api-test.sh` exercises header preselection, session-init, mem-command, and reset behavior.
- `E2 test verified`: `MemoryProxy/scripts/qa/p1-dump-verify.py` verifies outbound-body injection rather than only intermediate logs.
- `E2 test verified`: `sdk/memory-core/python/tests/test_v3_transport_timeout.py` covers timeout behavior in the Python transport.

The end-to-end flow is: bootstrap and storage setup -> request preprocessing -> session-init orchestration -> memory-command short-circuiting -> storage-backed state updates -> QA verification of injected output. The remaining gap is a live proxy run against a real upstream and persistent backend. See [TencentCloud/TencentDB-Agent-Memory](../repositories/TencentCloud-TencentDB-Agent-Memory.md).

### docling-project/docling

This repository informs `document-ai-ocr` through a timeout-bounded conversion pipeline that preserves page structure and confidence reporting. The current head adds formatting-preserving Word extraction paths and LibreOffice hardening around the conversion pipeline, so the reusable mechanism is the partial-success conversion flow rather than the product-facing format zoo.

- `E1 source verified`: `docling/backend/msword_backend.py` expands paragraph and cell extraction with formatting-preserving logic.
- `E1 source verified`: `docling/backend/docx/drawingml/utils.py` adds LibreOffice profile and timeout hardening for conversion support.
- `E2 test verified`: `tests/test_backend_msword.py` covers trailing whitespace and rich-cell behavior in the Word backend.
- `E2 test verified`: `tests/test_failed_pages.py` and `tests/test_threaded_pipeline.py` cover page retention and timeout shutdown behavior.

The end-to-end flow is: format option selection -> backend dispatch -> threaded pipeline execution -> result integration with `PARTIAL_SUCCESS` handling -> final assembly with retained page structure. The remaining gap is a mixed-quality batch run under realistic OCR and resource pressure. See [docling-project/docling](../repositories/docling-project-docling.md).
