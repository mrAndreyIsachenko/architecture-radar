## Detailed Reviews

### deepseek-ai/deepseek-harness

This repository still informs `ai-llm-systems` through a semantic checkpoint barrier, but the current release head broadens the mechanism around the barrier. `prepareProfile()` composes the profile tree from durable patch layers and rewrites the empty root config, `createAppReady()` only commits readiness after boot succeeds, and `runPlugin()` now isolates exact-version compatibility approvals from normal package operations. The headless semantic-checkpoint tests still prove that an interrupted session can replay an unknown tool outcome and that checkpoint storage failure blocks model dispatch rather than letting the request proceed.

The reusable mechanism is the combination of layered profile boot and checkpointed dispatch, not the release branding. Compared with a plain launcher, this code treats configuration composition as a durable operation and keeps readiness separate from process start. The main gap is still a live packaged session with a process-kill/restart cycle on the same ledger.

### TencentCloud/TencentDB-Agent-Memory

This repository remains a strong `ai-llm-systems` reference, but the current head moves it beyond a single rewrite proxy. `createApp()` wires route gates and storage activation, `stageTeamMemorySwitch()` can disable or preserve team-memory behavior per instance, `resolveUserSessionDefault()` validates account defaults against the live team/agent/task catalog, and `SkillSelectionService.select()` separates candidate retrieval, strategy choice, and loading. The session-trace assembler keeps streamed output normalized so the proxy can record it coherently.

The reusable mechanism is now a staged session-init path with explicit fallbacks and visibility, rather than a monolithic request rewrite. A generic proxy would forward traffic and stop there; this one keeps memory policy, session defaults, and skill loading as independent stages. The open gap remains a live upstream plus persistent backend deployment.

### PX4/PX4-Autopilot

This repository continues to inform `drones-robotics-autonomy` through the commander ACK matrix and the safety gates around high-risk transitions. `Commander::handle_command()` and `Commander::answer_command()` still define the explicit accept/deny/temporary-reject/unsupported/failed contract, while `failsafe_test.cpp` and `escChecksTest.cpp` pin the policy around lost control, mission failure, wind, and ESC-health conditions. The current head expands validation with the new Gen Nav estimator test path and refreshed mission-failure coverage in the MAVSDK harness.

The reusable mechanism is the explicit ACK-and-failsafe contract, not the vehicle stack as a whole. The current head is useful because it broadens test surface without changing the contract, but it still does not replace live SITL proof. The main gap remains simulator-backed validation of the current safety envelope.
