## Detailed Reviews

### deepseek-ai/deepseek-harness

The harness connects CLI dispatch, exact-version plugin approval, JSONL session persistence, replay fixtures, and a two-process lock test into one recoverable boundary. The verified flow runs from `runCli()` to plugin approval to JSONL session materialization and finally to semantic checkpoint replay. The useful mechanism is the replay-safe harness boundary, not the DeepSeek branding. See [deepseek-ai/deepseek-harness](../repositories/deepseek-ai-deepseek-harness.md).

The main gap is live restart validation on the same interrupted semantic checkpoint. The source and tests show replay intent and lock takeover, but not a real process-kill plus restart on one live session.

### TencentCloud/TencentDB-Agent-Memory

The proxy layers hot cache, durable session rows, binding rows, and metadata-backed rebuild into one recovery chain. The verified flow runs from route registration through `hydrateFromDb()`, `getOrRecover()`, `probeL2a()`, and `rebuildFromBinding()` back into write-through persistence. The useful mechanism is the layered recovery chain, not the product naming. See [TencentCloud/TencentDB-Agent-Memory](../repositories/TencentCloud-TencentDB-Agent-Memory.md).

The main gap is live restart validation of hydrated initialized sessions. The source shows the recovery chain, and tests show recalled memory is not treated as new user input, but the review did not validate a real proxy restart with persisted sessions already in place.
