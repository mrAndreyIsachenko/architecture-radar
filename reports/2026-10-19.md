The concrete problem here is mixed-document extraction where born-digital and scanned pages share one pipeline and one confidence model. The useful mechanism is that page-quality heuristics change routing and confidence, but the document shape stays stable enough to audit. The baseline comparison is a conventional document converter that either flattens everything into raw text or renders every page eagerly. Docpipe instead delays expensive work until the structural pass has enough information to decide where it is worth paying for OCR or VLM reads.

Reusable points:

- Route pages independently so one degraded page does not poison the whole document.
- Keep confidence as a calibrated, page-aware signal instead of a single opaque score.
- Use an evaluation harness to compare pipeline variants on the same corpus.

- Do not treat backend choice as free; the repository still couples behavior to actual OCR/VLM availability.
- Do not assume the evaluation harness proves production performance on a live mixed corpus.

Production-quality signals:

- The same pipeline shape is exercised by integration tests, backend tests, extraction tests, confidence tests, and evaluation tests.
- The repo keeps provenance, auditability, and confidence as first-class concepts rather than afterthoughts.

Experimental or incomplete for our needs:

- Live backend/runtime combinations still need corpus-level validation.
- The repo proves deterministic source-level behavior more strongly than operational latency or failure recovery.

Hidden costs and failure modes:

- Adaptive routing can drift if page-quality thresholds are tuned against the wrong corpus.
- Confidence fusion can hide bad pages if downstream consumers only read document-level summaries.
- Backend diversity increases integration cost and makes deployment drift easier.

### drillcoder/voryn

This repository informs `blockchain-intelligence` through a strict ordered chain commit pipeline. `HeadService.execute` seeds or rebases the chain cursor and enqueues missing block jobs; `FetchService.execute` claims work, fetches block data, and marks jobs fetched or failed; `SequencerService.execute` validates parent hashes and either advances the chain cursor or rolls back to a common ancestor; and `ReactionService.execute` waits for confirmations, loads events or transactions, and advances worker cursors only if the reorg version still matches. See [drillcoder/voryn](../repositories/drillcoder-voryn.md).

- E1 source verified: `src/services/head-service.ts::HeadService.execute`, `::initializeCursor`, and `::rebaseCursorAndEnqueue` seed, rebase, and enqueue jobs around the live head.
- E1 source verified: `src/services/fetch-service.ts::FetchService.execute` and `::processClaimedJob` claim jobs, fetch block data, and mark jobs fetched or failed with retry handling.
- E1 source verified: `src/services/sequencer-service.ts::SequencerService.execute`, `::rollbackReorg`, and `::findCommonAncestor` enforce parent-hash continuity, delete orphaned rows, and rewind worker cursors when the chain forks.
- E1 source verified: `src/services/reaction-service.ts::ReactionService.execute` and `src/repositories/postgres/worker-cursors-repository.ts::advanceIfVersion`, `::rewindForReorg` gate reaction progress by reorg version and cursor position.
- E2 test verified: `test/integration/services/reaction-history-gap.test.ts::test("${stream} gap update blocks concurrent retention until its cursor is saved")` and `::test("${stream} rejects a gap detected before a PostgreSQL reorg rollback")` verify history-gap handling and rollback coordination.
- E2 test verified: `test/integration/services/transactional-reactions.test.ts::test("${streamType} commits business writes and progress together and resumes after restart")` verifies transactional progress and restart behavior.
- E2 test verified: `test/unit/services/sequencer-service.test.ts::test("sequencer service rolls back to common ancestor on parent hash mismatch")`, `test/unit/repositories/postgres/worker-cursors-repository.test.ts::test("rewindForReorg updates affected and lagging cursors in one statement")`, and `test/unit/postgres/leader-lock.test.ts::test("unlocks and returns a healthy client")` pin the reorg rewind, cursor update, and leader-lock behavior.

The concrete problem here is incremental chain indexing without corrupting derived materialization when blocks reorg. The useful mechanism is the separation of head polling, block fetch, ordered commit, and reaction handling, with reorg versioning as the guard that keeps stale work from advancing. The baseline comparison is a naive indexer that writes directly off the latest head and assumes the chain never rolls back. Voryn instead makes the rollback window explicit and keeps the downstream worker cursors versioned so they can be rewound with the chain.

Reusable points:

- Keep live head polling separate from fetched-block storage and from ordered commit.
- Use version-gated cursor advancement so stale reaction batches cannot advance after a reorg.
- Treat orphan removal as a first-class rollback path instead of relying on sink idempotency alone.
- Keep leader election and fetch claims explicit so one worker owns one commit stream at a time.

Do not copy:

- Do not copy the PostgreSQL schema as a generic indexing schema without the same commit semantics.
- Do not assume the integration tests prove live RPC churn or storage pressure.
- Do not weaken the reorg guard by advancing cursors before the transaction commits.

Production-quality signals:

- The implementation has clear boundaries between head, fetch, sequencer, reaction, and repository layers.
- The tests cover leader-lock behavior, reorg rewind, transactional progress, and history-gap handling.

Experimental or incomplete for our needs:

- Live RPC churn and restart pressure still need operational proof.
- The current evidence is strongest for source-level correctness, not for fleet-scale behavior.

Hidden costs and failure modes:

- A bad RPC endpoint or a missing block job can stall the sequencer.
- Reorg rollback depends on the downstream stores tolerating deletions and replay.
- Version gating can cause reaction batches to stop early, which is correct but operationally visible.

Adoption experiment:

Run the pipeline against a live RPC feed or forked chain, inject reorgs and storage pressure, and confirm the cursor, worker versions, and rollback deletes stay coherent across restart.

### JosefHobler/stm32-ccsds-node

This repository informs `satellites-space-systems` through an embedded TM/TC loop with watchdog recovery. `app_start` creates the UART mutex, alive event group, and sensor queue; starts the sensor, telemetry, telecommand, and watchdog tasks; and re-arms UART receive interrupts. `telecommand_task` frames CCSDS packets from a stream buffer, dispatches commands, and slips past bad CRCs or headers. `telemetry_task` emits periodic housekeeping and heartbeats. See [JosefHobler/stm32-ccsds-node](../repositories/JosefHobler-stm32-ccsds-node.md).

- E1 source verified: `Core/Src/app.c::app_start`, `::watchdog_task`, and `HAL_UART_RxCpltCallback` create the task set, enforce the heartbeat window, and feed single-byte UART interrupts into the telecommand path.
- E1 source verified: `Core/Src/telecommand_task.c::telecommand_task`, `::dispatch`, `::framed_total`, and `telecommand_uart_rx_isr` implement stream-buffer framing, command dispatch, ACKs, reboot handling, and byte-slip resynchronization.
- E1 source verified: `Core/Src/telemetry_task.c::telemetry_task`, `::tm_set_period_ms`, and `::emit_hk` implement periodic housekeeping and heartbeat pacing.
- E2 test verified: `cpp/tests/conformance_test.cpp` covers round-trip encoding, byte-identical encode/decode, corrupted CRC rejection, truncation rejection, wrong-version rejection, and out-of-range field rejection.
- E2 test verified: `cpp/tests/framer_test.cpp` covers complete frames, split frames, garbage-prefix slip, corrupted-frame recovery, back-to-back frames, and truncated-frame buffering.
- E2 test verified: `cpp/tests/differential_test.cpp` cross-checks decode/re-encode against Python-generated frames, and `cpp/tests/codec_test.cpp` pins CRC and fixture behavior.

The concrete problem here is command/telemetry on a delayed or noisy link where framing errors, partial frames, or task stalls can otherwise deadlock the control loop. The useful mechanism is the combination of stream-buffer framing, byte-slip recovery, and a watchdog that only refreshes when all tasks have checked in. The baseline comparison is a simple serial protocol loop that assumes clean bytes and never proves recovery on hardware. This repo instead makes bad frames recoverable and makes stalled tasks visible to the reset logic.

Reusable points:

- Keep one task responsible for framing and one for telemetry emission.
- Use a byte-slip resynchronizer instead of assuming headers are always aligned.
- Gate watchdog refresh on explicit task heartbeats.
- Keep cross-language codec conformance tests so firmware, ground station, and host tooling agree on wire format.

Do not copy:

- Do not copy the demo serial REPL shape as a production ground station.
- Do not assume the conformance tests prove hardware timing or UART noise tolerance.
- Do not rely on reboot ACKs without an external operator or harness verifying the restart path.

Production-quality signals:

- The firmware, ground station, and codec tests all describe the same wire format.
- The watchdog path and slip-resync path are explicit in source, not implicit in comments.

Experimental or incomplete for our needs:

- Real flashed-board runtime behavior still needs proof.
- The review did not validate watchdog recovery under induced noise or reboot churn.

Hidden costs and failure modes:

- A stuck task will deliberately let the watchdog reset the board.
- Framing state can drift if the UART path is noisy and the host never drains the queue.
- Runtime safety depends on the telemetry heartbeat staying below the watchdog window.

Adoption experiment:

Flash the firmware to target hardware, connect the Python ground station, inject malformed and partial frames, and confirm the watchdog and slip-resync paths recover without deadlocking the control loop.
