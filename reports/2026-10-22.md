## Detailed Reviews

### RightNow-AI/AutoMegaKernel

This repository informs `ai-llm-systems` through correctness-gated megakernel search. The reusable mechanism is not the profiler branding; it is the locked schedule edit surface, the validate-before-measure loop, and the persisted trial ledger that let an agent optimize latency without trusting a wrong kernel.

The verified flow runs from graph import to schedule search: `schedule.graph.ModelGraph` turns a decoder into explicit structural metadata, `harness.propose` exposes the editable `ScheduleConfig`, `schedule.search.search` lowers and validates candidates before scoring them, `eval.bench.bench` refuses to emit latency for an incorrect kernel, and `harness.loop` / `autoresearch` persist trial rows and campaign state. `tests/test_harness.py` and `tests/test_autoresearch.py` pin the honesty rule, rejected-config behavior, checkpoint/resume, and warm-start flow.

- E1 source verified: `harness.py:13-37` defines the `propose` / `evaluate` / `loop` contract and states that latency is never emitted without correctness.
- E1 source verified: `schedule/search.py:13-33,85-145,239-260` implements explore/exploit search, lower-before-score, and keep/revert selection around validated candidates.
- E1 source verified: `eval/bench.py:5-26,127-209` enforces the correctness gate and refuses to report latency for a wrong kernel.
- E2 test verified: `tests/test_harness.py:41-155` covers proposal shape, broken-config rejection, crash-free evaluation, loop logging, and CLI smoke.
- E2 test verified: `tests/test_autoresearch.py:33-100` covers unattended runs, results logging, corpus population, checkpoint/resume, move-on plateau behavior, and warm starts.

Production-quality signals are the explicit correctness gate, the stable trial log, and the fact that invalid configs fail cleanly instead of corrupting the search. The main limit is operational rather than source-level: the reviewed evidence still needs a real CUDA run to prove the measured path under device timing.

### juanfont/headscale

This repository informs `privacy-networking-vpn` through reconnect recovery, route approval, tagged-node reauthentication, and DNS certificate issuance under churn. The reusable mechanism is the control-plane split between session-aware reconnect handling, authoritative DNS propagation waits, and change-detected peer-map rebuilding.

The current head wires `dns.NewChallenges` into startup, and `Challenges.Present` publishes TXT records while tracking per-node ownership and lifetime. `dns.AwaitTXT` / `txtChecker.wait` then follow CNAMEs, resolve authoritative nameservers, and wait for every authoritative server to serve the challenge value before returning. On the policy side, `PolicyManager` retains the peer-recompute gate, `buildPeerMapPairScan` keeps the old pair-scan behavior as a reference, and `TestReloadPolicyRebuildsPeerMapOnChangeOnly` proves that changed policies rebuild once but idempotent reloads do not. `TestSetDNS` and `TestACMETLSSettings` pin the authenticated DNS path and the ACME/TLS integration.

- E1 source verified: `hscontrol/dns/challenge.go:23-207` implements challenge TTL, lifetime extension, per-node limits, ownership transfer, propagation waits, and provider append/delete semantics.
- E1 source verified: `hscontrol/dns/propagation.go:28-237` implements authoritative TXT propagation waits, CNAME chain following, nameserver lookup, and not-propagated errors.
- E1 source verified: `hscontrol/policy/v2/policy.go:32-103,198-220` implements policy validation, cache invalidation, auto-approver resolution, and the peer-recompute metadata gate.
- E2 test verified: `hscontrol/policy/v2/peermap_scan_test.go:17-80,295-833` validates the indexed peer-map builder against the reference pair-scan behavior.
- E2 test verified: `hscontrol/state/reload_policy_test.go:17-88` confirms a policy write rebuilds once on change and not on repeated reload of the same state.
- E2 test verified: `hscontrol/servertest/setdns_test.go:21-88` confirms unauthorized SetDNS attempts are rejected and certificate domains follow node renames.
- E2 test verified: `hscontrol/app_tls_test.go:191-240` proves the ACME settings work with DNS-01, HTTP-01, and TLS-ALPN-01.

The main limit is still runtime: live reconnect storms, multi-node HA churn, and authoritative DNS propagation under real latency remain unproven. Source quality is strong, but adoption should still wait for operational validation.

### ArduPilot/ardupilot

This repository informs `drones-robotics-autonomy` through mission failsafes, RTL fallback, telemetry/status reporting, and rover circle-direction validation. The reusable mechanism is the combination of explicit safety state machines and shared autotest helpers that prove both recovery ladder behavior and mission geometry assertions.

The copter-side failsafe monitor detects a stalled main loop, reduces motor output, and then disarms repeatedly while the failsafe remains active. The RTL mode remains staged, with explicit transitions through climb, return, hold, descent, and land. The rover autotest path adds a separate vertical flow: `PositionTargetGlobalIntAltFrame` uses `MAV_CMD_NAV_LOITER_TURNS` to trigger circle mode, `wait_circling_point_with_radius` and `wait_circle_direction` assert the vehicle stays on the circle and travels in the requested direction, and `test_gcs_failsafe` exercises telemetry-loss recovery plus mission continuation.

- E1 source verified: `ArduCopter/failsafe.cpp:1-72` detects a 2-second main-loop lockup, reduces motor output, logs the failure, and then disarms every second while the failsafe remains active.
- E1 source verified: `ArduCopter/mode_rtl.cpp:80-226,245-260` implements staged RTL setup, terrain-aware fallback, and explicit stage transitions through return, hold, descent, and land.
- E1 source verified: `Tools/autotest/rover.py:5919-5955` triggers Rover circle mode with `MAV_CMD_NAV_LOITER_TURNS` and checks that `POSITION_TARGET_GLOBAL_INT.alt` is AMSL-correct.
- E1 source verified: `Tools/autotest/rover.py:1986-2074` drives GCS-failsafe disabled, enabled, recovery, mission continuation, and timeout cases.
- E2 test verified: `Tools/autotest/vehicle_test_suite.py:19533-19625` provides reusable helpers for radius and circle-direction assertions.

The production-quality signal is that the safety ladder and the mission geometry checks are both explicit, not implicit. The remaining gap is simulator validation: the rover circle-direction path and the recovery ladder still need a live SITL run before they should be treated as operational proof.
