### openziti/ziti

This current-head refresh keeps `privacy-networking-vpn` focused on the reconnect path that resends the full router-link state with wire-level confirmation, but it now fences refresh and listener debt by reconnect generation. The source path is explicit in `router/link/link_registry.go` and `router/link/ctrl_sync.go`, and `router/link/link_registry_test.go` plus `router/link/ctrl_sync_test.go` now cover stale refresh invalidation, queued-but-never-written announcements, and one-in-flight refresh behavior. `go test ./router/link ./router/env ./tests -run 'Test_NotifyOfReconnect|TestCheckHeartBeat|TestNotifyOfConnectivityChange_ReconnectReportsBothHalves'` passed on this runner.

See [openziti/ziti](/home/runner/work/architecture-radar/architecture-radar/repositories/openziti-ziti.md).

### librespacefoundation/satnogs-network

This repository informs `satellites-space-systems` through future-observation materialization, station/client eligibility gating, and cleanup tasks that keep scheduled observations aligned with TLE and transmitter updates. The useful mechanism is the delayed-connectivity scheduling gate, not the Django product wrapper.

`network/base/managers.py`, `network/base/perms.py`, and `network/base/tasks.py` define the connected/location slices, the schedule permission matrix, and the future-observation refresh workers; `network/base/tests.py` exercises the scheduling permissions. The reviewed evidence did not run locally because `pytest` is unavailable on this runner.

See [librespacefoundation/satnogs-network](/home/runner/work/architecture-radar/architecture-radar/repositories/librespacefoundation-satnogs-network.md).

### librespacefoundation/satnogs-client

This repository informs `satellites-space-systems` through a serialized observation session: the scheduler claims a job, the observer computes pass geometry and tracking inputs, the rotator and rig workers follow the pass, and the post-run file posting layer uploads results back to the network API. The useful mechanism is the pass-bound capture loop, not the client packaging.

`satnogsclient/scheduler/tasks.py`, `satnogsclient/observer/observer.py`, `satnogsclient/observer/worker.py`, and `satnogsclient/observer/orbital.py` define the run loop, tracking workers, and upload behavior; `satnogsclient/tests/test_artifacts.py` and `robot/testsuites/SatNOGS_client.robot` cover artifact creation, startup, job polling, rotator flip, and job serialization. The reviewed evidence did not run locally because `pytest` is unavailable on this runner.

See [librespacefoundation/satnogs-client](/home/runner/work/architecture-radar/architecture-radar/repositories/librespacefoundation-satnogs-client.md).
