## Detailed Reviews

### rmax-ai/durable-agent-runtime-lab

This repository contributes a deterministic durable-agent runtime pattern: workflow creation, planning, scheduler promotion, proposal verification, execution, and append-only state recording are all split into separate modules, but the `run_goal` path still behaves like one bounded workflow. The useful mechanism is the proposal boundary plus hash-chained event ledger, not the benchmark framing. See [rmax-ai/durable-agent-runtime-lab](../repositories/rmax-ai-durable-agent-runtime-lab.md).

The main gap is runtime validation after an actual process-kill and restart. The source and tests already show deterministic fault injection and the durable path, but not a live recovery run on the same workflow ledger.

### EspiroFares/Autonomous-UAV

This repository contributes a canonical hold boundary for autonomy safety. Mission state derives from world-model freshness, the follow controller degrades stale inputs into safe hover or hold, the hold policy normalizes unsafe paths into one command shape, and the FCU bridge remains the only actuation gateway. See [EspiroFares/Autonomous-UAV](../repositories/EspiroFares-Autonomous-UAV.md).

The main gap is longer SITL churn: repeated target loss, world-model silence, and bridge restarts still need to prove the canonical hold path remains stable under repeated recovery.

### nasa/HDTN

This repository contributes a contact-plan-driven DTN control plane. The router recomputes routes from time-based contacts, physical link changes, and storage state; egress applies those route updates; and the bundle storage manager persists, restores, and accounts for segmented bundles. See [nasa/HDTN](../repositories/nasa-HDTN.md).

The main gap is operational validation under contact-plan churn plus storage pressure. The source shows the route and storage plumbing, but not the combined live behavior under delayed transport and restoration pressure.
